# Rasputin post-v1 backlog

This is the parking lot for work that is intentionally outside the frozen
ten-slice v1 finish line. It prevents a release-candidate gap from becoming
unbounded scope. Nothing here is part of the v1 release claim until it receives
its own bounded plan and acceptance evidence.

## Evidence still needed before v1 can be called fully release-ready

- Run a real authenticated browser Workstation/Assistant keyboard-and-mouse
  pass and attach a redacted operator record.
- Register a reachable local coder model and complete the edit -> test failure
  -> repair -> diff review mission.
- Complete one authenticated local STT -> Assistant -> TTS turn with browser
  microphone permission and speaker hardware.
- Perform a stopped active-data upgrade rehearsal in addition to the verified
  separate-target restore and isolated migration rehearsal.

## Deferred product work

- Measured sustained throughput and runtime-specific model-placement certificates
  for the operator's hardware.
- Additional local voice models, wake-word/background audio, or always-listening
  behavior (only with a separate privacy and approval review).
- A standalone external MCP server, only if the internal capability contract is
  proven insufficient.
- Broader connectors, plugin marketplace work, fine-tuning, cloud memory, or
  arbitrary autonomous computer control.
- Major UI redesign, public-store signing, update channels, and enterprise
  collaboration features.

See [`RASPUTIN_V1_RELEASE_CONTRACT.md`](RASPUTIN_V1_RELEASE_CONTRACT.md) for
the authoritative non-goals and stop rule.
